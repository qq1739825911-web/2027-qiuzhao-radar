## 用户长期要求（每次续接都必须保留）

1. **岗位颗粒度一致。** 一条记录对应一个具体岗位；不把招聘计划、公告、专业目录、行业分类、栏目标题、HR 联系话术、职责正文或多个职位拼接文本当成真实岗位名称。
2. **可信度分区不能混淆。** “可优先核验岗位”和“待核验线索”分开显示。公开列表卡片或无法安全打开的链接不能冒充已核验详情岗位。
3. **优先核验要有证据。** 应具备具体岗位名、真实雇主、岗位级详情链接、明确的 2027 届证据、近期链接核验和近期重新发现记录；旧届、过期、社招/实习误入、失效记录应降级或移出优先区。
4. **重点扩展应届生求职网。** 优先研究并采集其公开招聘列表、专业/职位分类页、分页、公开详情链接；保持轮转与增量更新，不只看首页或有限几家大厂。
5. **信源和岗位类型要够广。** 覆盖央国企、民企、上市公司、中小企业与不同专业，包含设计、AIGC/AI 视频/漫剧、新媒体、电商、运营、市场、行政、财务、销售、产品、数据、工程等，不要把产品缩成只服务用户本人求职方向的小站。
6. **分开统计采集层次。** 页面可访问、发现岗位卡片、识别出具体岗位、岗位级详情可访问、满足优先核验条件，是不同状态；采集数或线索数不等于有效正式岗位数。
7. **只采集允许公开访问的页面。** 不绕过登录、验证码、反爬/安全墙、隐私限制或私有 API。BOSS 详情被安全验证阻止时，只显示公开卡片线索。
8. **逐小阶段验收。** 如实区分代码已提交、自动化测试通过、数据采集完成、数据已提交、Pages 部署成功、浏览器交互测试通过，不提前宣称未验证事项已完成。
9. **避免重复劳动与中断。** 每次新对话先查本文件、README、最新提交、manifest、Actions 状态；在前一轮采集未结束时不要连续改动导致任务被取消。
10. 用户曾反馈页面体验问题：AIGC 搜索无结果、搜索和页面速度慢、详情文字混入 JSON 垃圾文本、详情关闭按钮错位、届别标签错位。涉及 UI 修改时需覆盖搜索同义词、城市组合筛选、详情文本清洁、按钮布局、Esc 关闭、收藏/投递看板、画像保存和信源监控。
